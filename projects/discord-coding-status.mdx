**Discord Coding Status** keeps Discord Rich Presence in sync with your AI coding sessions through a small daemon running on your own computer.

It combines lifecycle hooks with process detection, enriches the activity with sanitized project metadata, the active model, and optional native quota, then publishes the result through Discord Desktop's local RPC connection. It is not a Discord bot and does not require a bot token, public server, or cloud relay.

## Supported tools

Each tool gets its own Discord application identity, so what appears in Discord is the harness you are actually using.

| Tool | Activity source | Native quota |
| --- | --- | --- |
| Codex CLI / Codex in ChatGPT desktop | Lifecycle hooks + process fallback | OAuth or app-server RPC |
| Claude Code / Claude Desktop | Lifecycle hooks + process fallback | Subscription OAuth |
| Grok Code | Lifecycle hooks + process fallback | Billing API |
| OpenCode CLI | Process detection | OpenCode Go usage |
| Pi | Process detection (or the bundled extension) | — |
| Cursor IDE / CLI | Process detection | Cursor dashboard usage |

When several tools are active at once, the daemon publishes presence only for the session updated most recently and clears the others — Discord shows one activity per user, so a stale background process never wins over the terminal you are typing in.

## What Discord displays

The default `project` detail level produces two lines:

```text
Bash survived the assignment | my-project @ main
claude-sonnet-4-6 | Pro • 5h 75% • weekly 60%
```

Quota percentages are shown as *remaining*. Three privacy levels decide how much of that is filled in:

- `safe` shows the activity and model only.
- `project` adds sanitized project, branch, and quota.
- `full` also includes the package name.

Full filesystem paths, prompt text, transcript content, account emails, secrets, repository URLs, and raw commands are never used as Rich Presence text. Context usage is fail-closed: it appears only when a hook supplies a numeric metric such as `42%` or `128k / 256k`, and free-form context text is discarded.

Activity text comes in four styles — `fun` (`Bash survived the assignment`), `normal` (`Using Bash`), `technical` (`Running npm test`), and `minimal` (`Working`).

## How it works

1. Managed lifecycle hooks for Codex, Claude Code, and Grok Code publish session changes immediately. Process detection keeps desktop apps, OpenCode, Pi, and Cursor visible when native events are unavailable.
2. The daemon sanitizes project metadata, resolves the active model and reasoning effort, and optionally reads quota from the configured local source.
3. Activity is sent to Discord Desktop through its local IPC/RPC connection.
4. File watching plus a ten-second polling loop keep the status current across long-running sessions.

Quota refreshes run in the background, so a slow endpoint can never block a hook update from reaching Discord. The last known value is kept until fresh quota arrives.

## Key features

- Real-time updates from lifecycle hooks, with process polling as a fallback
- Six coding tools supported, each with a separate Discord identity
- Active model and reasoning effort on the presence line, e.g. `gpt-5.6-sol · xhigh`
- Optional plan and remaining-quota display for Codex, Claude, Grok, OpenCode, and Cursor
- A full-screen config editor with a live preview of both Discord lines
- Automatic startup through a LaunchAgent on macOS or a Scheduled Task on Windows
- Integration and stress tests that run without an active Discord session

## Quick start

Discord Desktop and Node.js 18 or newer are required. Install the daemon and its startup entry with:

```sh
npx -y discord-coding-status@latest setup
```

Setup detects your installed tools, copies a self-contained runtime into your application-data directory, installs startup, and adds managed hooks for the tools it finds. Codex requires one manual approval — open Codex, run `/hooks`, and trust the managed command hooks.

Verify the installation, then start a session:

```sh
npx discord-coding-status status
npx discord-coding-status hooks status claude
npx discord-coding-status quota --tool claude
```

Tune what appears with the interactive editor:

```sh
npx discord-coding-status config
```

macOS and Windows have managed startup support. Linux users can run the daemon manually with `npx discord-coding-status daemon`.

## Local-first privacy

Session state stays on your computer. Discord receives only the short, sanitized Rich Presence strings selected by the configured detail level. There is no public HTTP listener, hosted backend, or telemetry service.

Quota lookup reads local credentials — Codex auth files, Claude Code OAuth from the Keychain, Cursor's local session token — talks only to that vendor's own usage endpoints, and keeps results in daemon memory. Tokens are never included in the Discord activity payload, and quota can be disabled per tool.

Managed hooks are marked as owned by this project, existing configuration is preserved, and the previous file is backed up before any write. Uninstall removes only what the installer added.
